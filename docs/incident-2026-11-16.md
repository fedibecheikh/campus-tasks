# Compte rendu d'incident — mise en service v0.9.0

- **Date** : 2026-11-16
- **Environnement** : staging (`compose.staging.yaml`, port 8080)
- **Version déployée** : `v0.9.0` (image défectueuse)
- **Version restaurée** : `v1.0.1`
- **Contexte** : l'image `v0.9.0` fournie par l'enseignant n'étant pas accessible depuis le registre du cours, elle a été **simulée localement** à partir du même code avec une écoute sur `127.0.0.1` au lieu de `0.0.0.0` (défaut classique décrit dans le tableau des erreurs fréquentes).

## Les cinq lignes demandées

1. **Ce qui s'est passé** : la version `v0.9.0` a été mise en service ; le conteneur a démarré mais l'application n'était joignable sur aucun port publié.
2. **À quel moment je l'ai su** : `docker compose ps` affichait le service `Up`, mais `scripts/wait-healthy.sh` a échoué après ses 12 tentatives (~60 s) avec `staging non sain` (code 1).
3. **Ce que j'ai fait** : lecture des journaux (`docker compose logs --tail=50 api`), première erreur utile identifiée — `* Running on http://127.0.0.1:8080` — puis retour arrière en remettant `IMAGE_TAG=v1.0.1` et en relançant `docker compose --env-file .env.deploy -f compose.staging.yaml up -d`.
4. **Durée d'indisponibilité** : environ 75 secondes (60 s de détection par le contrôle de santé + ~5 s de rollback), sans reconstruction d'image.
5. **Ce qui empêcherait la reproduction** : rendre le contrôle de santé bloquant avant toute mise en service (le job de publication ne doit livrer qu'une image dont `/health` répond), et vérifier l'adresse d'écoute (`0.0.0.0`) dans l'image candidate.

## Première erreur utile (recopiée telle quelle)

```text
api-1  |  * Running on http://127.0.0.1:8080
```

Cause : l'application écoute sur l'interface de boucle locale **du conteneur**.
Le port publié `8080:8080` arrive sur l'interface réseau du conteneur, pas sur
son `127.0.0.1` ; la connexion est donc refusée même si le processus tourne.
